### 🤖 Auto Work Trackers: setup, teardown and employees first

**Auto Work Trackers (sidebar → Auto Work Trackers), Create work trackers.**

- **Setup and teardown are now part of every trip it plans.** A trip that picks a bleacher up from an event gets **Teardown Required**, and every trip gets **Setup Required** at the event it is dropped at. Each comes with its line item at the driver's setup or teardown rate from their profile, the same as ticking the boxes in the work tracker window. Each takes an hour on site, which counts towards the driver's day. For now the driver who hauls the bleacher does both.
- **Employees before contractors.** The model fills employees' days first and gives contractors what is left. A contractor is a driver paid through a vendor. On **Driver Data**, **Driver Availability** and **Driver Workload**, each driver's name now says **(employee)** or **(contractor)** underneath.
- **Advanced settings (button under Create work trackers).** How the model plans, in one place:
  - how strongly employees come first: off, prefer employees, or employees first;
  - least distance or least drive time;
  - the longest day;
  - setup and teardown time;
  - the hour the day starts;
  - how long it searches for a better plan.

  Each setting shows whether it is the default, with **Reset to default**. **Admins** can change them, and the next run uses them right away, no update needed. Account managers can see them. After each run, the result lists the settings it used.

- **Driver schedule:** setup and teardown now show as their own amber blocks, an hour each.

### 📝 Teaching the model: Runs, and "why did you change this?"

- **Model → Runs (new page in the Auto Work Trackers panel).** Every click of Create work trackers is recorded: who ran it, when, and with which settings. For each trip it planned, the page shows whether it was **kept**, **edited** (and exactly what changed, e.g. the driver or the day) or **deleted**. It also counts the week's work trackers made by hand before and after the run.
- **Work tracker window:** when you save changes to, or delete, a trip the model made, it now asks **why** in a few words, e.g. "the driver can't make it that day". It's optional (**Skip and save**). Your answers show on Runs and tell us what the model gets wrong.
- **Delete model drafts** also asks why (optional). The run is kept on Runs, marked **Discarded**, so trying different settings doesn't count against the model.

### 💬 Claude connector

- **Claude answers questions about our data more accurately.** It now knows the rules the app uses, for example that revenue includes tax, which events count as booked, currencies, and days in Toronto time, so its numbers match what you see in the app.
- **"Where is bleacher #12?"** Claude can now read the bleachers' GPS trackers: where each bleacher is now, and where it stood over any window of up to the last 7 days. The **Permissions** page says GPS positions are included.

### 🔒 Who can do what

- **Advanced settings:** admins change them; account managers can see them.
- **Model → Runs:** admins and account managers can open it. Anyone who edits or deletes a model trip can give a reason.
