# Preflight — 1.13.0

PR: #392
Status: passed
Signed: 2026-09-15 against fd44259

This is a large release — a whole new Venues system, the contact/venue
picker redesign, Lost Reason, and declined/abandoned tracker counts are
each independent features bundled into one branch. A dozen items can't
cover all of them exhaustively; the list below is the highest-risk path
through each, not a tour.

**One important thing before you start:** while reviewing this PR I found
and fixed a real data bug — see the first item under "Could have broken."
The fix (commit `fd44259`, plus a regression test) is on this branch but
**not yet pushed to the PR**. Push it before this merges, or every save of
an existing venue-linked quote will silently unlink its venue in
production.

## New in this release

- [x] **Quote form → Venue field.** Search for an existing venue, pick one;
      type something new and use "+ Create New Venue"; click the pencil on
      the selected card and edit it in place. Each works without leaving
      the field.
- [x] **Quote form → Contact / Finance Contact fields.** Same as above —
      search, "+ Create New Contact", inline edit via the pencil.
- [x] **Work Trackers → open a Trip tracker → Pickup POC / Dropoff POC.**
      Same picker as the quote form. Also: open a tracker a driver
      **declined** or **abandoned** (or set one to that status) as a lead
      AM or admin — a **"Back to Draft"** button appears next to the
      badge; click it, Save, reopen — status is Draft.
- [x] **Quote → Contract tab.** Click the Contact name — a sidesheet opens
      listing that contact's other events, **Future Events above Past
      Events**, each row linking to that quote. Click the Venue (on a
      quote that has one) — same sidesheet, same order.
- [x] **Quote Details → Status → Lost**, no reason picked → Save is
      refused with a toast. Pick "Price too high" → saves. Open the
      Contract tab → the reason shows under Status.
- [x] **Dashboard → open an event → Details tab → Status → Lost.** Same
      requirement as above, in the _other_ place that can set Lost — this
      one has no automated test covering it.
- [x] **Dashboard → open any event → Details tab.** Contract Revenue is
      gone from this tab (it's now derived automatically from line items
      and tax).
- [x] **Work Trackers sidebar**, with a driver who has a declined or
      abandoned trip in your zones — a red count shows next to Work
      Trackers, next to that trip's week, and next to that driver inside
      the week.

## Could have broken

- [x] **Open a quote that already has a Venue assigned, change nothing,
      hit Save, then reopen it — the Venue is still linked**, not reverted
      to a plain typed-in address. (This is the bug described above —
      before the fix, every quote with a venue silently lost that link on
      its next save. A unit test now covers the load path, but the actual
      save-and-reload round trip is worth clicking once.)
- [x] **Manage Team → a driver → Home Address**, and **Storage Locations →
      an existing location.** Reopening each shows the full street, city,
      state, and zip — not just the street (the same fix touched 6+
      address fields across the app; these two weren't part of the main
      Venues work, so they're the ones most likely to have been missed).
- [x] **Dashboard grid**, a bleacher with an unresolved damage report:
      confirm its colored strip starts on the report's date and
      disappears once a maintenance event is scheduled for it. Visual/
      canvas — nothing else can check this.
- [x] **Companies & Contacts → + New Contact**, and editing an existing
      contact from that page. The shared modal these pickers now also use
      gained new fields and props — worth one normal create/edit to
      confirm the original page still works exactly as before.

## Permissions

No new role or page was added. Two things folded into existing rows in
[`permissionPageData.ts`](src/features/userAccess/permissionPageData.ts),
already updated in this PR:

- **Companies & Contacts** now explicitly covers Venues — same rule as
  contacts and companies (admin/account_manager full, viewer read-only,
  everyone else no access). Verified against the live RLS policies on
  `Venues` (`venues_select`/`_insert`/`_update`), not just the client code
  — they match exactly, and there's no delete policy because deleting a
  venue is a soft-delete through the update policy.
- **Declined & Abandoned Work Tracker Counts** is a new row: admin (only
  when also an active account manager) and account_manager get counts
  scoped to their own zones; everyone else sees nothing. Checked against
  `resolveWithdrawnScope` — matches the doc.

**One thing to decide, not a regression:** the new "Back to Draft" button
is gated by the same `canEdit && canRelease` check as the existing
Draft/Released toggle (leads and admins) — but that gate itself has never
been written into `permissionPageData.ts`'s "Work Trackers" row, which
only describes create/edit/delete in general terms. Pre-existing gap, not
introduced by this PR, but the new button makes it more visible. Want me
to add a line documenting who can release/revert a tracker's status while
I'm in this code?
