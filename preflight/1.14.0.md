# Preflight — 1.14.0

PR: #395
Status: passed
Signed: 2026-09-17 against 9263975

This release is two branches merged together: pagination and event-instructions
work on `contact-event-history`, and a larger batch — companies/contacts forms,
the quote form's popups, bleacher type descriptions, the alerts data-layer
migration off Zustand/Pusher — on `q3-sprint6-more-info`. The merge itself
touched `DropDown.tsx`, resolved by hand in favor of the shared
`panelPosition`/`estimateListHeight` positioning system both sides had built
independently — that resolution has not been seen running in a browser yet by
anyone, which is why it leads the "Could have broken" list below.

Most of the underlying logic is already covered by unit tests, new integration
tests against a real in-memory SQLite, and two new Playwright specs. What's
below is what only a person can judge: that the new UI actually renders where
it's supposed to, and that heavily-edited shared files (the work tracker modal,
the dropdown component, the alerts data layer) still behave normally on the
paths this diff didn't set out to change.

## New in this release

- [x] **Quotes & Bookings page.** Change rows-per-page to 50, go to page 2,
      reload the browser — you land back on page 2 at 50 rows, not page 1.
      Click into a quote and use the browser back button — same result.
- [x] **Quotes & Bookings → edit a quote → scroll to Internal Notes.** A
      Dropoff Instructions / Pickup Instructions row now sits under it. Type
      something in each, save, reopen the quote — both are still there.
- [x] **Work Trackers page → open a trip assigned to a bleacher with a nearby
      booked event before and after it → Details tab.** Click the locate icon
      next to Pickup Instructions — it fills in from the previous event's own
      Pickup Instructions. Do the same for Dropoff Instructions with the next
      event. Above the Pickup and Dropoff columns, a small card names that
      neighboring event with its dates — click it and it opens that event's
      page in a new tab.
- [x] **Same work tracker modal.** The Pay field is gone — the total now shows
      once, next to Delete and Save at the bottom, and it matches the Line
      Items total exactly. Scroll the Details tab — the Details/Line Items
      tabs and the type switch at the top stay in place instead of scrolling
      away.
- [x] **A trip run on a different bleacher than assigned.** Confirm it shows in
      the red count in the sidebar, on its week, and against that driver —
      then open it and set the actual bleacher to match the assigned one. The
      count drops by one everywhere it showed.
- [x] **Approve a quote whose contact has a Finance Contact with a company set
      on it.** Open the quote page and the PDF — the finance contact's company
      name and address show next to Contact in both, not the main contact's.
- [x] **Quote form → add a bleacher line item.** The type's description shows
      on the line. Go edit that bleacher type's description in Pricing Matrix
      (admin), then reopen the already-created quote — its line item still
      shows the old wording, not the new one.

## Could have broken

- [x] **Dropdown menus generally** — this is the merge-conflict resolution
      nobody has run yet. On the work tracker modal, open the Bleacher select
      and a line item's Type select; open one near the bottom of the screen
      and confirm it flips upward with room to scroll instead of running off
      the edge, and that scrolling inside the open list doesn't close it.
- [x] **Work Tracker save, on a trip with no other pending edits.** Change only
      a line item's quantity or amount and hit Save — it saves. This exact
      guard ("No changes to save") blocks every save on the modal if it's
      wrong, not just line items.
- [x] **A work tracker's address and POC locate buttons** — untouched on
      purpose, but their underlying query was rewritten this release to match
      an existing performance optimization. Open a trip on a bleacher with
      neighboring events and click both address locate buttons and both POC
      locate buttons; each still fills in the same value it did before.
- [x] **Create, then edit, a contact or company from inside the Quote form**
      (not the Companies & Contacts page) — set a billing and shipping address
      on create, save, then reopen and edit something unrelated. Both
      addresses are still there. The dedicated Companies & Contacts page has
      an e2e test for this same bug; this checks the other entry point into
      the same new shared form.
- [x] **Dashboard → open an existing event's modal → Details tab.** Alerts
      (Scheduling Conflict, seat mismatch) still show correctly for an
      ordinary event. This release replaced the entire data layer feeding
      these alerts (Zustand/REST/Pusher → PowerSync); the new e2e suite covers
      several scenarios, but not a plain existing event you pick yourself.

## Not testing

  gets written to the URL while data is still syncing) — `pagination.test.ts`
  and `filterUrlSync.test.ts`.
- **Contact/company create-then-edit from the Companies & Contacts page**,
  search matching company address and language, and blocking a duplicate
  email — `companiesContactsForms.admin.spec.ts` (Playwright, added this
  release).
- **Quote form popups fitting the screen**: the Add Line Item dialog scrolling
  its list, the contract template dropdown opening above with no room below,
  notes resizing up to 6x, the payment schedule's labelled button —
  `createQuoteLayout.am.spec.ts` (Playwright, added this release).
- **Scheduling Conflict firing for an event with no explicit setup date** — the
  actual bug fixed this release — covered by `occupiedBoundary`'s unit tests
  and scenario S2 of the new end-to-end alerts suite, which seeds exactly that
  case.
- **The bleacher-swap counting query and week/driver bucketing** —
  `attentionTrackerScope.test.ts` and `attentionTrackers.test.ts` cover the
  SQL and the grouping logic directly; the manual item above only checks that
  the number lands and clears in the UI.
- **Which contact's company gets shown (finance contact vs. main contact, and
  address formatting)** — `quoteDocumentData.test.ts`.
- **The bleacher type description snapshot itself** (copied at add-time, not
  live-linked) — `toEventLineItemValues.test.ts`.
- **The rewritten address/POC/instructions/adjacent-event SQL** — each has a
  new integration test running the real query against `node:sqlite`, proving
  the `LIMIT 1` version returns what the unbounded version returned, including
  the tie-break and legacy-free-text edge cases.
- **The "Work Tracker Still in Draft" alert's removal** — it's a straight
  deletion of the alert definition and its cron sync; nothing to verify beyond
  its absence, which you'll simply never see.
- **The Pusher/Zustand removal itself** (dead code, unused env vars) — no
  behavior for it to have changed; the existing suite ran clean before and
  after, per the commit.
- **"Go to current sprint" on the Roadmap page** — developer-only, not part of
  either AM or admin day-to-day work.
- **Anything on the PixiJS dashboard grid canvas, or in the driver mobile
  app** — unreachable from this repo's test tooling either way; not directly
  touched by this release's logic changes.
