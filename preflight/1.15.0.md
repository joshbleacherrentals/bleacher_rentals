# Preflight — 1.15.0

PR: #404
Status: planned

A big release: 21 commits, 165 files and 15 migrations. The features are well covered by tests
(about 50 changed test files, pgTAP included). Most of the risk here is in two places the tests
can't reach:

- **Production data.** Existing payment schedules are converted from dollars to percentages.
  New triggers now run on every save of `Events`, `BleacherEvents`, `WorkTrackers` and
  `Addresses`.
- **Deployment.** pg_cron runs in production for the first time. There are new PowerSync sync
  rules for maintainers and for drivers' finished trips.

None of the merge commits needed a conflict resolved by hand (`git show --remerge-diff` is empty
for every one), so no form lost a field that way.

**This is past the size one person can verify by hand.** The list below stays at a dozen items
by relying on the automated coverage and on being run against production data.

## New in this release

- [ ] **Quote page → Send To Client**, on a quote whose contact and finance contact are both your
      own email addresses. The review window lists both in To. It shows the subject, the email
      body, and a desktop/mobile switch. Each attachment opens in a new tab, and the quote PDF is
      in the contact's language. Press **Cancel**: no email arrives. Open it again and press
      **Send**: a spinner, then a check mark, and one email arrives with the PDF attached.
- [ ] **Quote form → Send Quote →** on a brand-new quote, then **Cancel** in the review window.
      The quote is saved, and its status is still Draft, not Quoted. Send it for real: the status
      becomes Quoted and the email arrives.
- [ ] **New quote defaults.** As an admin, set a Default Sales Office on an account manager's
      profile (Team page). Mark a contract template as default on Terms & Conditions. Sign in as
      that account manager and click **+ Create Quote**. Both are already selected, and the
      payment schedule shows 50% / 50%.
- [ ] **Sales Offices → edit a US office → Payment Info.** Click into the field. The dialog moves
      left and a sample quote appears beside it. Type two lines and save. Open the customer link
      of an approved quote from that office: both lines show on the Approved Quote tab, as typed.
      An office with Payment Info left blank shows no e-transfer line at all.
- [ ] **Dashboard → options menu → Hide all Subrentals.** Every subrental row disappears, even on
      dates right next to a subrental. Reload the page: it stays on. Sign in as another user: it
      is off for them. Then open an event whose bleacher is subrented into the zone you have
      selected: that bleacher is pinned once, not twice.
- [ ] **Dashboard alert dots.** An event 3+ weeks out with no transportation has no red alert dot.
      An event that ends this Sunday or earlier (next Sunday if today is Thursday or later), also
      with no transportation, does have one. An event with a damaged bleacher but no other
      problem has no dot, but still shows the red damage mark on the cell.
- [ ] **Dashboard → Ctrl/Cmd+click a cell** to create a Work Tracker next to an event that has
      Pickup/Dropoff Instructions. The new tracker opens with those instructions already filled
      in, along with the addresses.
- [ ] **Production, as the maintainer user:** Damage Reports and Repairs both list real records,
      not an empty page. Empty pages would mean the PowerSync sync rules were not deployed with
      this release.

## Could have broken

- [ ] **Existing payment schedules, converted by migration.** Open 2–3 existing quotes from before
      this release that have a custom schedule (not 50/50, ideally one partly paid). Each row's
      dollar amount matches what it showed before the release, the percentages add up to 100%,
      and a paid installment still shows as paid. Check the edit form and the customer link.
- [ ] **Other automatic emails.** This release rewrote the shared email sender. Sign a test quote
      as the customer from its public link. The customer's confirmation arrives with the PDF
      attached. The account manager's "quote signed" email arrives too, and
      finance@bleacherrentals.com gets a copy of it.
- [ ] **Saving events with the new triggers.** On the dashboard, take a bleacher off an event that
      shares it with another event on overlapping dates, then save. The save succeeds. Open the
      other event: its "Double booked" alert about the first event is gone.
- [ ] **Finished work trackers.** In the Work Tracker modal, change a line item on a completed
      trip and save: it saves. In the driver app, as a driver with finished trips, open one: its
      addresses, line items and inspections all still show.
- [ ] **Terms & Conditions page.** This page's saving code was rewritten. Create a template, edit
      its text, set it as default, then delete it. Each change sticks after a reload. After the
      delete, no template is default and a new quote starts with none selected.
- [ ] **Nightly alert cleanup.** The morning after deploying, run
      `select * from cron.job_run_details order by start_time desc limit 5` in the production
      Supabase SQL editor. `delete-past-alerts` ran and succeeded.

## Permissions

The matrix already has entries for this release's three permission changes: maintainers now get
full access to **Damage Reports** and **Repairs & Maintenance**, there is a new **Contract
Templates** entry, and **Edit Team Members** now covers the default sales office. Postgres does
not enforce two of these. Before this ships:

1. **Default sales office (AccountManagers).** The matrix says an account manager "can see it but
   not change it." But the `rbac_update` policy on `AccountManagers` lets any account manager
   update **any** account manager's row, including `default_sales_office_uuid`. Only the UI
   stops them.
2. **Default contract template (TermsAndConditions).** The spec records your decision (2026-09-21)
   that only admins can set templates. But the policies on `TermsAndConditions` let **any signed-in
   user** insert and update, and that now includes `is_default`. This policy was already loose
   before this release; the new flag makes it matter more.

Also not in the matrix:

3. **Sales Offices** has no entry at all. In practice, admins, account managers and viewers can
   open `/sales-offices`, but only admins can write (`sales_offices_insert/update`). The new
   Payment Info field is admin-only in Postgres.
4. **Sync Health** (`/dev-tools/sync-health`) has no entry. Developers only.
5. **Sending a quote.** Neither the send route nor the new `send-preview` route checks the role
   (spec decision 2: "not now"). The preview route uses the service key, so any signed-in Clerk
   user can read any quote's email body and recipients by its id. That includes drivers and
   maintainers.
