## New in this release

- [x] **A typed price survives.** Open the seeded **Price Repro: Bullhead rally** quote → **Edit**.
      The 10-Row line reads **2 × $5,400**. Change **Event Type** to **City**, then back to
      **Corporate**: the 10-Row stays **$5,400** both times.
- [x] **A matrix price still follows.** On the same quote, the 15-Row line is locked at **$3,500**.
      Change **Event Type** to **City**: it moves to the City price for a one-day rental on its own.
      Change the dates to ten days: it moves again.
- [x] **Pencil and reset arrow.** On a locked line the icon is a pencil: click it and the price
      becomes typeable. Type a new price: the line total updates. The icon is now a reset arrow:
      click it and the matrix price comes back. On an event type or dates with no matrix price the
      reset arrow is greyed out.
- [x] **"Prices have changed" before saving.** On the same quote, change the **Event Type** so the
      15-Row moves, then **Save**: a window lists the 15-Row (old → new) and the line items total
      before tax. **Go back** leaves the quote unsaved and open. Save again → **Save with new
      prices**: it saves, and reopening the quote shows the new price.
- [x] **Same check on Preview PDF and Send Quote.** With a price changed, press **Preview PDF**, then
      **Send Quote →**: each shows the same window first, and **Go back** stops it.
- [x] **No window when nothing changed.** Open any saved quote, change only a note, **Save**: it
      saves with no price window.
- [x] **A new quote remembers too.** **New quote** → add a bleacher line, press its pencil, type your
      own price, **Save**, then **Edit** the quote: the line still shows your price with the reset
      arrow (not locked).

## Could have broken

- [x] **A new quote still saves and totals add up.** Create a quote with two bleacher lines, a service
      and a discount: it saves, and reopening it shows the same lines and the same total.
- [x] **Existing quotes are untouched.** Open a quote saved before this release → **Edit**: every
      bleacher price is exactly what was saved, each with the reset arrow. **Save** without touching
      anything: no price window, the total is unchanged.
- [x] **A signed quote.** Open a booked, signed quote → **Edit**, change only a note, **Save**: no
      price window, and the signature behaves as it did before this release.

## Not testing

- Rules for which line is re-priced, which price counts as changed, matching a line after a save
  gave it a new id, and the totals in the window — `linePrice.test.ts` (21 cases; I broke two rules
  on purpose and both were caught).
- The window's text and numbers — `PriceChangeDialog.test.tsx`. Its **width** is not tested: the
  layout was changed after the screenshot that showed it overflowing and not looked at again — check
  it by eye on first use.
- The flag being saved and read back, and an old row or draft with no flag counting as "typed by you"
  — `toEventLineItemValues.test.ts`, `fetchLineItems.test.ts`.
- The column itself — boolean, not null, defaults to true, accepts the 0/1 the app uploads, and
  flipping it never changes `content_hash` or `contract_hash` (so it cannot cancel a signature) —
  `event_line_items_is_price_overridden.test.sql` (8 assertions, run green in a rolled-back
  transaction).
- Who can do this: nothing changes. Editing a quote and saving its lines are the same writes by the
  same roles; the new column inherits the table's four `authenticated`-only policies, and `anon` is
  still refused by row-level security. `permissionPageData.ts` needs no entry.
- Old lines being marked "typed by you" — deliberate, by migration default; there is no way to tell
  afterwards which saved prices were typed.
- The PixiJS dashboard grid and the driver mobile app — untouched by this PR.
