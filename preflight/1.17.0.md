# Preflight — 1.17.0

PR: #410
Status: passed
Signed: 2026-10-08 against 2238c69

A medium release: 12 commits, 65 files, three migrations (`dev_allowed_emails`, `perf_events`,
`events_is_tax_overridden`). The database rules are covered by pgTAP (`dev_allowed_emails`,
`events_is_tax_overridden`, `perf_events`) and the logic by unit tests. What those cannot tell you
is whether **production** is wired up: the migrations, the PowerSync sync rules in `br_powersync`
(a new developer-only stream for `DevAllowedEmails`, which needs a PowerSync restart), and that
real emails still go out.

The one merge in the PR (`27fb41f`) had no conflicts and touched no file on both sides, so nothing
was dropped from a form.

**Deploy in this order**: apply the migrations to production Supabase, then deploy `sync_rules.yaml`
and restart PowerSync, then deploy the app. Rules that name a table which does not exist yet are
the one thing here that can take sync down.

## New in this release

- [x] **Tax follows the price (existing quote).** As an account manager, open **Quotes & Bookings**
      → a quote saved before this release → **Edit**. Change a line item's price: the **Tax** row
      and the total change with it, and the label has no "— overridden".
- [x] **A typed tax sticks, and Reset puts it back.** On the same form click the tax amount and
      type a different one: the label reads "Tax (x%) — overridden" and **Reset to calculated
      tax** appears. Change a price: your tax does not move. **Save**, reopen **Edit**: still
      overridden, same amount, no red "could not be saved" toast. Click **Reset to calculated
      tax**, **Save**, reopen: automatic again. The quote's **Log** tab shows **Tax Typed By Hand**
      going No → Yes → No. Then create a brand-new quote with a line item: tax calculates with no
      "overridden", and stays that way after Save and Edit.
- [x] **Status button.** On **Quotes & Bookings**, click the coloured button (top right, next to
      Show Deleted) five times: **All Statuses** (grey) → **Booked** (green) → **Quoted** (amber) →
      **Lost** (red) → **Draft** (violet) → back to All. Each step lists only that status and
      shows a "Status: …" chip (none on All); the filter sidebar's Status field shows the same
      value. In the sidebar pick two statuses: the button turns blue and reads **Custom Statuses**,
      and the next click goes to **Booked**.
- [x] **Open a quote in a new tab.** On **Quotes & Bookings**, Cmd-click (Ctrl-click on Windows) a
      row: the quote opens in a background tab and the list stays where it was. Right-click a row:
      the browser menu offers **Open Link in New Tab**. A plain click opens the quote in place.
- [x] **Dates on chat messages.** Open **Messages → Internal → a chat**, and a quote's **Messages**
      tab: every message shows the date before the time, like "Oct 1, 9:44 AM", in both places.
- [x] **Picker focus.** Reload **Quotes & Bookings → + Create Quote**, click **Contact** and type
      straight away: the letters land in the search box without a second click. Reload and do the
      same on **Venue**.
- [x] **Allowed Emails (Development copy, green banner).** As a developer, **Dev Tools → Allowed
      Emails** lists the seeded addresses; add one, edit it, delete it. As an admin, open
      `/dev-tools/allowed-emails` by URL: you are sent away. Then send a quote to an address that
      is not on the list: the quote's **Automatic Emails** tab shows it failed with "Blocked in
      development" and nothing arrives. Add the address, send again: it shows sent and arrives.

## Could have broken

- [x] **Production wiring, right after deploy.** In production as an admin and as a developer,
      reload: **Dashboard** and **Quotes & Bookings** list real records, and the PowerSync logs
      show no error naming `DevAllowedEmails`. As a developer, **Dev Tools → Allowed Emails** opens
      (an empty list is correct in production). Empty pages or a sync error mean the rules went out
      before the migration, or PowerSync was not restarted.
- [x] **Real emails still go out, in production.** There is no coloured banner at the top, and
      `NEXT_PUBLIC_ENVIRONMENT` in Vercel's production settings is not `development`. Sign a test
      quote whose account manager is you: the client email, and the account-manager email with
      finance copied, both arrive, and the quote's **Automatic Emails** tab shows both **sent**
      and none "Blocked".
- [x] **@mention and task emails.** In a quote's **Messages** tab @mention a teammate: they get
      "You were mentioned in …". As a developer, post on a Roadmap task another developer follows:
      they get "New message on: …". Both routes were rewritten around the new filter.
- [x] **Other tables sharing the table component.** As an admin, **Accountant → AR**: click a row
      and the quote opens, and the rows are as roomy as before. **All Work Trackers** renders the
      same as before.
- [x] **Pickers inside pop-up windows.** **Companies & Contacts → open a contact → Edit**: click
      the **Venue** picker. The cursor lands in the search box, you can pick a venue, and the
      window stays open. **+ Create New Venue** from that dropdown still opens its own window.

  says it "measures nothing yet". Five unit-test files and `perf_events.test.sql` (13 checks) cover
  it, and the Vercel build for this PR passes.
- **Who can read and change the Allowed Emails list** — `dev_allowed_emails.test.sql` (29 checks):
  developers only, all four operations; checked against `pg_policies` too.
- **Which emails the Development copy drops** — unit-tested (`guardRecipients`, `sendTriggerEmail`):
  a blocked CC is dropped while the To still goes, an unreadable list blocks everything, and
  staging, production and an unset variable change nothing.

  false, the app's integer 0/1 is stored as a boolean (also confirmed against a real local
  PostgREST, PATCH and upsert), flipping it never changes the quote or contract hash so it cannot
  invalidate a signature, admins and account managers can change it, accountants and viewers
  cannot.
- **Status cycle order and the tax override rules** — unit-tested (`statusQuickFilter`,
  `taxOverride`, `loadQuoteIntoStore`, `logEventChanges`).
- **Rows rendering as links** — unit-tested in `DataTable.test.tsx`; the click behaviour is on the
  list above.
- **Customer quote page, PDF, signing and payments** — untouched; the hash test shows the new flag
  cannot disturb a signature.
- **Permissions page** — gained a "Development Email Allowlist" row, which matches the database;
  nothing else in the PR changes who can do what.
- **The Clerk token-lifetime change** that cut Vercel usage — made in Clerk's dashboard, not in
  this PR.
- **Dashboard grid and driver mobile app** — untouched; the sync rules only add a developer-only
