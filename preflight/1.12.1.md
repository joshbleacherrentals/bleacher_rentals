# Preflight — 1.12.1

PR: #385
Status: passed
Signed: 2026-09-14 against 258017d

A small, self-contained fix: when creating a QuickBooks bill fails, or any
QuickBooks call fails because a connection's token needs refreshing, the
error shown now names the actual problem and where to go fix it, instead of
a generic string. Read every commit and both changed source files —
`create-bill/route.ts` and the shared `util.ts` token-refresh helper — plus
the two new pure functions and their tests. The rest of the diff
(`supabase/seed.sql`, ~85k lines) is a local/CI-only production data refresh
with five `ON CONFLICT DO NOTHING` fixes to `supabase db reset` — it never
touches a deployed database and has nothing to click.

**While writing this, CI actually failed** on that seed.sql refresh — a
second, different bug from the five I'd already fixed: `ci-pr.yaml` pins the
Supabase CLI to `2.101.0`, five-plus minor versions behind
`package.json`'s `^2.116.0` and the `latest` every other workflow uses. That
old CLI's bundled storage-api schema predates the `versioning_status` column
on `storage.buckets`, so CI's auto-seed on `supabase start` failed with
"column does not exist" — before ever reaching the duplicate-key issue the
`ON CONFLICT` fixes address. Bumped the pin to `2.116.0` to match
`package.json`. This is now part of the same commit set on this branch — CI
passing on the PR is the check for this one, nothing to click by hand.

## Permissions

This PR changes no role-gated behavior — the error message a user sees is
identical regardless of who's looking at it, and no new page, button, or
API route was added.

One thing adjacent to this PR worth your call, not a regression it
introduces: `create-bill` and `get-bill` are guarded by `requireAuth()`
(any signed-in user) in the code, while the two sibling QuickBooks
Configuration pages — Quickbooks Connections and Work Tracker Types — are
both `admin`-only in
[`permissionPageData.ts`](src/features/userAccess/permissionPageData.ts:367-397)
and use `requireAdmin()` server-side (`tax-codes/route.ts`). Nothing in the
UI currently exposes "Create Bill" to a non-admin, so this is unlikely to
be reachable today, but the API itself doesn't stop a non-admin who hits it
directly. Pre-existing, not introduced here — flagging in case it's worth
tightening to `requireAdmin()` at the same time you're in this code, or
leaving as-is if it's already covered by how the Work Trackers page itself
gates who sees that button.

## Not testing

- `interpretQboBillError` and `describeQboAuthError` themselves — both are
  pure functions with 9 unit tests between them (`interpretQboBillError.
test.ts`, `describeQboAuthError.test.ts`) covering every fault shape this
  fix targets, plus fallback behavior for anything unrecognized.
- Simulating the full live QuickBooks failure end-to-end in an automated
  test — would mean mocking the entire `intuit-oauth-ts` + `fetch` stack for
  a scenario the unit tests already prove correct once the real fault JSON
  reaches the mapping function; the manual items above check it against
  actual QuickBooks, which is what actually matters here.
- The content of the refreshed `supabase/seed.sql` itself — it's a raw
  production dump, not something to spot-check row by row, and it never
  runs against a deployed database. The reset-collision fix is the only
  part with user-visible risk, and that's on the manual list above.
