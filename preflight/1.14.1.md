# Preflight — 1.14.1

PR: #398
Status: passed
Signed: 2026-09-17 against 23fbc10

A small release: one behaviour change on the dashboard grid. Subrental ("ghost")
rows are now hidden unless the dates on screen come within two weeks of one of
their subrentals. Four files, no migration, no new table, no new write path.

The date maths is covered by 15 unit tests, so nothing below re-checks "does 14
days mean 14 days." What is left is everything the tests cannot see: the grid is
drawn on a PixiJS canvas, and every time the visible set of subrental rows
changes, the whole grid is torn down and rebuilt. That rebuild is the risk in
this release, not the filter.

## New in this release

- [x] **Dashboard, a zone with a known subrental.** Scroll horizontally to a
      month with no subrentals anywhere near it — the borrowed bleacher's row
      is gone from that zone. Scroll back until you are two weeks out from the
      subrental's start — the row is back, in its usual place by bleacher
      number.
- [x] **A long subrental (a month or more).** Park in the middle of it, far
      from both ends — the row is still there. It should only vanish once you
      are more than two weeks past the end.
- [x] **A pending (not yet accepted) subrental.** Its row follows the same
      rule — visible from two weeks before the start, not only accepted ones.
- [x] **Requested Sub-Rentals popover (the flashing handshake button).** Pick a
      pending request whose dates are months away and click it. The form opens,
      and its bleacher's row stays on screen the whole time the form is open,
      wherever you scroll. Set it to Accepted and save — it saves normally.

## Could have broken

- [x] **Vertical position while scrolling sideways.** Scroll down into the
      middle of a long bleacher list, note which bleacher is at the top of the
      screen, then scroll horizontally across a date where subrental rows
      appear and disappear. That same bleacher stays at the top — the list must
      not jump up or down under you.
- [x] **Ordinary bleacher rows are never hidden.** With a zone filter on, count
      the normal rows on today's dates, then scroll a few months out and count
      again. Same rows, same order — only subrental rows come and go.
- [x] **Editing a cell while the grid rebuilds.** Open a cell for editing
      (double-click a note), type something, and scroll sideways far enough to
      cross a point where a subrental row appears. Confirm you either keep the
      editor or lose it cleanly — no ghost editor floating over the wrong cell,
      no text landing on a different bleacher.
- [x] **Dragging a work tracker after rows have changed.** Scroll until a
      subrental row appears or disappears, then drag a work tracker onto
      another bleacher and date. It lands on the cell you dropped it on.
- [x] **Creating an event with bleachers selected.** Open the event form, pick
      a few bleachers so they pin to the top of the grid, then scroll months
      away. The pinned rows stay pinned, and the form still saves with the
      bleachers you picked.
- [x] **Fast horizontal scrolling.** Drag the horizontal scrollbar quickly
      across a year. It should stay smooth — the rebuild waits until you stop.
      Watch for flicker, a frozen header row, or the scrollbar jumping back.
- [x] **Events view (Y axis = Events) and Optimization mode.** Switch to each
      and scroll sideways. Neither is meant to be touched by this change —
      confirm rows behave exactly as they did before.

## Not testing

- **The two-week rule itself** — which dates show a row, accepted vs pending,
  a subrental with no dates, timestamps vs plain dates, "exactly 14 days" on
  both ends — `subrentalRowVisibility.test.ts`, 15 unit tests added in this PR.
- **The row-anchoring maths** (`anchoredScrollY`) — it lives inside the Pixi
  `Dashboard` class and is only meaningful as a visual result, which is the
  manual item above. Extracting it purely to test it was not worth changing the
  shipped code.
- **Anything else on the dashboard grid canvas** — cells are drawn, not DOM
  elements, so Playwright cannot see them at all.
- **Permissions** — nothing to test; see below.
- **Database behaviour** — this PR adds no query, no column and no write. The
  same rows, with the same access, are simply drawn less often.

## Permissions

No change, and nothing added to `permissionPageData.ts`. Every role sees the
same rows they saw before, with the same edit rights — the rule is about when a
row is drawn, not about who may see or touch it, and it applies identically to
`admin`, `account_manager`, `developer`, `viewer`, `driver` and `maintainer`.
The existing **Dashboard Cells** entry still describes this page correctly.

I did not query `pg_policies` for this release: the diff touches four
client-side files, adds no table, column, migration or write path, and I am
concluding nothing about who can write.

**One question for you.** A hidden row cannot be clicked. The only way I found
to reach a far-future pending subrental is the Requested Sub-Rentals popover,
which is unaffected (and the row stays pinned while that form is open, which is
the fourth item above). If your account managers reach pending subrentals any
other way — by scrolling to them on the grid and clicking the row directly —
tell me, because that path is now blocked outside the two-week window, and the
fix belongs in the code rather than on this checklist.
