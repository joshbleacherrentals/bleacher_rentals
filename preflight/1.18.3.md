## New in this release

- [x] As an account manager with a lot of alerts, open the bell. The list is the same as before this release (same alerts, newest reminder first). Dismiss one — it leaves the list and the badge count drops by one. An alert for an event that already ended does not show.
- [x] As user A, subscribe to a chat. As user B, post in it and then post again with an @mention of A. A's header bell shows the chat as unread, the @mention one is listed first and marked, and the count is one per chat (not per message). Open the chat — the badge goes away.
- [x] Open **Messages → Internal**. The same chats appear as before, in the same order, with the right unread marks and last message. Open one chat and go back — its unread mark is gone.
- [x] Open a chat's **Members** window as an admin. Add someone — the "added to the chat" toast shows, "<you> added <them> to the conversation." appears in the chat, and they now show as a member. Remove them — same, with "removed … from the chat."
- [x] As an account manager, **Leave chat**. "<you> left the chat." appears, the chat drops out of your list, and Join puts you back.
- [x] Reload the app with two tabs open. Both finish loading with no red errors in the browser console, and a busy page (Quotes list, a chat with many messages) opens at least as fast as on 1.18.2.

## Could have broken

- [x] Open a chat that has 10 or more messages you have not read. All of them are marked read: the badge clears, the sender sees you in their read receipts, and reopening the chat does not create duplicates or show an error toast.
- [x] Go offline (browser DevTools → Network → Offline), add a member to a chat, post nothing else, then go back online. After a few seconds the member and the "added" message are on another user's screen — both or neither, never only one.
- [x] As an accountant: Join a chat, post, then Leave. All three work, "left the chat" appears, and the three-dot menu has no Members option (an accountant cannot add or remove anyone).
- [x] As a viewer: open a chat with unread messages. You can read it, there is no error toast, and the unread mark clears for you. You cannot post, join or leave.
- [x] A chat for a deleted event never shows in the header bell count, even if it had unread messages.

## Not testing

- Roles and who can add, remove, post or leave in a chat — the app's rules and the live database policies (`pg_policies`) agree with the Event Chat entry in `/permissions`; this release changes none of them. Only the accountant, viewer and add/remove checks above prove the new single-transaction writes still pass them.
- That the new alert and chat lists return exactly what the old queries returned — covered by the differential unit tests in this PR, which run both versions against the same data.
- The "one transaction" behaviour itself (rollback when a write fails) — covered by `typedWriteTransaction.test.ts` and `conversationActions.test.ts`.
- The 300 MB database cache — no visible setting; I only look for speed and errors in the first item of the list.
- Sync rules / "role overlap" (step 3 in `docs/specs/slow-local-db-step3-role-overlap.md`) — stopped and not in this PR; nothing changed in `br_powersync`.
- Supabase CLI 2.116 → 2.120 — a developer tool, not shipped to users.
- The Dashboard grid (PixiJS) and the driver mobile app — nothing in this diff touches them.
